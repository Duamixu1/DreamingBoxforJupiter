# 三个版本 · 需求说明

给三个并行对话用：每个对话负责一个版本。开工前先读完这一页，再读 [README.md](../README.md) 和 [幻境版方案.md](幻境版方案.md)。

## 一句话

同一个手摇空间音乐盒：转动摇柄，小火车穿过一段旅程，终点抵达一封信。我们要做三个**故事不同**的版本：

| 版本 | 方向 | 目录 |
| --- | --- | --- |
| A · 西方玄幻 | 希腊神话 / 欧洲传说：天马、独角兽、神殿、星座 | `stories/western/` |
| B · 东方山海 | 《山海经》、庄子等古籍：鲲鹏、青鸟、仙山、灵兽 | `stories/eastern/` |
| C · 普通人 | 真实的旅行与回忆：家、第一次远行、海边、城市夜晚 | `stories/everyday/` |

## 最重要的要求：先定故事，再做 3D

上一版（幻境版 demo）是先搭 3D、再往里塞元素，所以显得简陋，很多东西经不起推敲：鲲为什么在这里，青鸟从哪来，场景之间是什么关系。这次倒过来做：

1. **定故事**：选一个**有出处**的故事或选段，比如古籍里的某一篇、某个神话章节，也可以是一段完整的原创叙事。写清楚起点、经过、终点，以及每一站发生了什么。
2. **拆场景**：把故事拆成 3–5 站。每一站写清楚这几项：
   - 地点、时间（清晨 / 白天 / 黄昏 / 夜晚）、天气
   - 主角是谁、在做什么
   - 前景、中景、后景、远景分别有什么（裸眼 3D 靠层次出效果）
   - 这一站和上一站怎么衔接，比如穿云、过桥、入夜
3. **出概念图**：用 Tripo 和图像模型先出每一站的概念图和关键角色。核对它们是否**符合原典描述、符合场景逻辑**：比例、季节、光线、谁出现在哪里。
4. **列模型清单**：根据确认的概念图，列出要用 Tripo 生成的模型和提示词，格式参考 [Tripo模型清单.md](Tripo模型清单.md)。
5. **最后才搭 3D**：概念确认之后，再接进原型代码。

每个版本至少交付：`story.md`（故事与出处）、`scenes.md`（分站拆解）、`refs/`（概念图）、`models.md`（模型清单）。

## 引用原典的规矩

- 古籍（《山海经》《庄子》、希腊神话的古典版本）是公版，可以引用原文。但要标明篇目，比如《山海经·西山经》、《庄子·逍遥游》、奥维德《变形记》某卷。
- 现代译本、现代小说、影视作品受版权保护，只取灵感，不要整段搬运。角色要原创设计，不要照搬现有的影视、游戏形象。
- 版本 C 用的如果是真实人物的照片和经历，要先得到当事人同意，不要放进公开仓库。

## 硬性约束（三个版本都一样）

| 项目 | 约束 | 原因 |
| --- | --- | --- |
| 画幅 | 竖屏 1200×1920，10:16 构图 | 透镜柱沿竖屏方向排布，横放会失去左右视差 |
| 时长 | 常速摇 60–90 秒，3–5 站 | 方案第 07、09 页 |
| 节奏 | 所有动作只读 worldTime：停摇，世界就静止 | 产品核心体验 |
| 结尾 | 终点抵达一封信，信的内容可以按版本改 | 方案主线 |
| 层次 | 每站都要有前景 / 中景 / 后景 / 远景 | 裸眼 3D 的立体感来自深度分层 |
| 性能 | 每个视点 ≤ 3 万三角面；尽量合批 | 每帧要画 9 个视点（RK3566 / Mali-G52） |
| 细节 | 不放小字、细密花纹、照片墙 | 真机上会串扰、看着"花"（明信片已经因此关掉） |

## 真机上学到的事（2026-10-02）

- 火车和布景的 3D 效果不错，整体不花；**明信片太花**，已关掉。
- 屏幕两侧不能露底色或深色内壁，读起来就是两块黑边。
- 画布必须贴齐屏幕左上角，偏一点交织相位就错，会发晕。
- 低多边形的白色云在近处像石块，近景雾气要用柔边粒子。
- 校准参数：Pitch 0.27777 / Offset 2 / Tan 10。这是官方参考值，本机标签没找到。

## 并行协作

- 三个对话各自只改自己的 `stories/<版本>/` 目录，避免互相冲突。
- 需要改共享引擎（`prototype/src/`）时，开单独的分支，比如 `story/western`，在说明里写清楚改了什么。
- 共享的东西（火车、轨道、信件、手摇节奏）尽量不动。版本之间的差异放在故事、场景和模型里。
